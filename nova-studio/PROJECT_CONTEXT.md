# NOVA Studio — рабочий контекст для ChatGPT

> Главный документ для восстановления целей, истории, текущего состояния и правил совместной работы над проектом.
> Обновлять этот файл при существенных изменениях проекта или договорённостей.

## 1. Зачем существует проект

NOVA Studio — учебный демонстрационный сайт для личного портфолио разработчика.

Это НЕ действующее digital-агентство и НЕ коммерческий сайт. Пользователь не планирует запускать его для реальных клиентов, покупать домен или развивать бизнес на его основе.

Задачи проекта:
- закреплять HTML, CSS и JavaScript на практическом примере;
- учиться читать, понимать и постепенно писать код самостоятельно;
- получить законченный, аккуратный проект, который можно показать в портфолио;
- постепенно развивать внешний вид и функциональность без ненужных переделок.

## 2. Откуда всё началось

Первоначально пользователь попросил подобрать удалённую работу без звонков: переписка, чаты, текстовые задачи, простые технические задачи или фриланс. У пользователя был небольшой опыт разработки сайтов и чтения кода, но не было готового портфолио.

В ходе обсуждения выяснилось, что полезнее не просто искать работу без примеров навыков, а создать несколько демонстрационных работ. В качестве практического проекта мы начали делать сайт креативной digital-студии NOVA Studio.

Поэтому исходный контекст — обучение и подготовка портфолио для будущих возможностей в удалённой работе. Сам сайт — учебная работа, а не заказ для клиента.

## 3. Как пользователь учится и как нужно помогать

- Пользователь начинающий в веб-разработке, знакомится с HTML, CSS и JavaScript.
- Он умеет читать код и хочет лучше понимать, как он работает.
- Объяснять простым языком, что делает конкретный фрагмент и почему изменение необходимо.
- Работать небольшими шагами: одна понятная задача → изменение → проверка в браузере → разбор результата.
- Не выдавать большие непрошенные переписывания файлов.
- Не просить без необходимости вставлять код в чат: сначала проверить актуальные файлы в Dropbox.
- Не считать, что пользователь хочет просто скопировать решение. По возможности объяснять логику и давать возможность самому внести небольшое изменение.
- Тон общения — дружелюбный, неформальный, поддерживающий; можно обращаться «брат», но без чрезмерного повторения.

## 4. Где находится проект и как устроена работа с файлами

Основная папка Dropbox: `/nova-studio`

Файлы проекта:
- `index.html` — структура страницы;
- `style.css` — стили, визуальное оформление и адаптивность;
- `script.js` — интерактивность;
- `README.md` — краткая инструкция по проекту;
- `ForGPT.md` — исторический файл с контекстом и фрагментами предыдущего диалога;
- `PROJECT_CONTEXT.md` — этот рабочий документ.

Рабочий процесс пользователя:
1. Пользователь открывает локальную синхронизируемую папку `nova-studio` в VS Code.
2. Редактирует файлы локально.
3. Сохраняет изменения через Ctrl+S.
4. Dropbox синхронизирует изменения в облако.
5. Ассистент читает актуальные версии файлов из Dropbox перед тем, как советовать изменения в соответствующей части проекта.

Dropbox — основной источник актуального состояния кода. Не полагаться на устаревшие фрагменты кода из истории чата.

Важно о возможностях:
- Ассистент может читать файлы из Dropbox через подключённые инструменты.
- Не утверждать, что ассистент может самостоятельно редактировать локальные файлы в VS Code.
- Не обещать автоматическую проверку Dropbox по таймеру или самостоятельное возвращение к файлам без нового сообщения.
- Перед изменениями заново получать актуальный файл из Dropbox, если пользователь мог его поменять.
- Если доступ к файлу или синхронизация не сработали, честно сообщить об этом, а не угадывать содержимое.

## 6. Важные детали реализации и история решений

### Мобильное меню
В `script.js` используется переключение класса `active` у `.nav` через `classList.toggle("active")`. Возвращаемое значение записывается в `isOpen` и передаётся в `aria-expanded`. При выборе ссылки меню закрывается и `aria-expanded` устанавливается в `"false"`.

Ранее была ошибка: значение `aria-expanded` сначала устанавливалось по `isOpen`, а затем сразу принудительно перезаписывалось на `"false"`. Ошибка исправлена; пользователь подтвердил, что меню работает.

### Scroll Reveal
Используется `IntersectionObserver`. Элементы получают класс `reveal`, а при попадании в область видимости — `is-visible`. После появления наблюдение за элементом прекращается через `observer.unobserve(entry.target)`.

В истории был эксперимент с отдельным CSS-свойством `translate`, после которого пользователь сообщил, что анимация стала резкой. Мы вернулись к варианту с `transform: translateY(...)` и `transition`. Пользователь подтвердил, что текущий вариант выглядит хорошо. Не возвращаться к эксперименту с `translate` без веской причины и согласования.

### Hover и transform
Ранее обсуждался возможный конфликт `transform` между Scroll Reveal и hover-эффектами карточек. Не начинать перестройку HTML-обёрток автоматически: сначала воспроизвести реальную проблему и убедиться, что она всё ещё существует. Текущий визуальный результат пользователя устраивает.

### Исторические фрагменты не являются текущим кодом
`ForGPT.md` содержит старые версии кода и советы, в том числе раннее применение класса `active` для Scroll Reveal. При расхождении приоритет:
1. актуальные файлы в Dropbox;
2. последние подтверждённые пользователем результаты;
3. этот документ как карта контекста;
4. старые сообщения и фрагменты в `ForGPT.md`.

## 7. Что не нужно делать

- Не предлагать публиковать сайт, покупать домен или готовить коммерческий запуск, если пользователь сам этого не попросит.

- Не менять рабочую анимацию, мобильное меню или адаптивность без обнаруженной проблемы.
- Не переписывать проект целиком и не добавлять сложные библиотеки без необходимости.
- Не выдавать предположения о текущем коде за проверенные факты.
- Не путать учебный проект с реальным агентством.

## 8. Как продолжать работу

В начале нового этапа:
1. Кратко восстановить цель: учебный проект для портфолио.
2. Уточнить из контекста, на каком этапе остановились; не задавать вопросы, ответы на которые уже есть в этом документе.
3. Если задача касается кода — прочитать соответствующие актуальные файлы из `/nova-studio`.
4. Предложить один конкретный следующий шаг, объяснить его смысл и дать пользователю выполнить/проверить его.
5. После подтверждения результата перейти к следующему шагу.
6. При существенном изменении проекта или правил работы обновить этот документ.

Не нужно каждый раз пересказывать пользователю весь этот файл. Использовать его как внутреннюю карту проекта и придерживаться его правил.
